# CargoNest design and API

Intent: partition a fixed public fictional set of indivisible parcels into identical capacity-limited containers. A reviewable discrete planning application, not procurement quantities, payments, actual dispatch, dimensional geometry or safe carriage certification.

Input: strict UTF-8 JSON {version:1,capacity:{weight,volume},max_bins,parcels:[{id,weight,volume}],incompatible:[[id,id]]}. 1..8 parcels, unique ASCII IDs1..24, positive exact integer weight/volume<=1000000; capacity integers1..1000000, max_bins1..8; <=28 unique symmetric normalized incompatibility pairs, no self/unknown/duplicate edges; booleans/floats/duplicate keys/extra fields rejected; raw1..16384bytes. Values are abstract declared units; no conversion or real carrier policy inferred.

Core: sort parcel IDs ASCII; enumerate all canonical set partitions as restricted-growth vectors, assigning each new parcel only to existing bins or one next-numbered bin. At most Bell(8)=4140 complete partitions. Enforce both capacity sums and pair incompatibility during search. Optimize minimum used bins, then lexicographic restricted-growth assignment. Every parcel appears once; no duplicated/skipped identity, capacity overrun or conflict can enter result. Infeasible (oversized parcel or max_bins limit) returns decision INFEASIBLE, empty assignments/bins and no physical packing claim. FEASIBLE output includes minimum bin count, fixed-order assignment vector and per-bin member IDs, integer weight/volume totals. Validator independently derives global optimum and exact tie, not just plausible schema.

API, zero constructor: open_load(load_id,url,sha256)->null captures strict manifest into OPENrev0; pack_load(load_id,expected_revision)->dict permissionless fresh fetch/hash/full solver into PACKEDrev1+domain cert; confirm_load(load_id,expected_revision,certificate_id)->null creator-only, FEASIBLE only, independent fresh full compute and exact match into CONFIRMEDrev2; revoke_load(load_id,expected_revision,reason)->null creator-only offline terminal REVOKED rev+1; get_load(load_id)->dict; get_configuration()->dict. ID/input locked; creator/CAS/cert checked, no replay. History binds actual chain time and operation. No funds or external dispatch.

Source/consensus/transaction boundaries match the stated common SDK infrastructure: hardened commit-pinned GitHub namespace + exact byte SHA; each validator independently fetches and recomputes complete source/optimum/binding. Transport and source truth not authenticated. Frontend starts without address; real MetaMask and Studio61999 only; complete write→finality→execution-success→read; unknown hash retained, never auto-retried; SDK decoded dictionaries only.

Dedicated UI: locked parcel table, two capacity metrics, conflict list, concrete container cards with weight/volume utilization and member IDs, exact assignment and certificate. It displays chain output and checks its partition/capacity shape; it never runs a host solver as the chain result. Local fixture is explicitly fictional and unpublished; no fake URL, deployment or hosting.

Tests: literal a/b and c/d partition; minimum bin and lex tie (independent literal optimum); second-dimension capacity, incompatible pairs, max-bin infeasible, oversized parcel, 8-parcel bound, permutation stability; invalid IDs/pairs/dupes/strict ints/fields/raw source drift/hash/namespace; independently forged assignment/bin totals/count/binding rejected; state creator/CAS/wrongcert/cross-ID/terminal/offline revoke; full exact SDK semantic/schema; dedicated frontend domain/receipt/SDK dict tests and tsc/Vite.
